# Prototype 27 — Resolution Strategy Succession

## Purpose

Test one bounded question from user-declared canonical v4.7.49 plus the validated v4.7.53 follower-Regulation lifecycle:

> When leader/follower Regulation matures into a later positively supported pure head-on, can Traffic Policeman select the already-demonstrated Refuge/Reposition strategy again without duplicate dispatch and without creating a second traffic Commitment?

## Expected sequence

1. Initial pure head-on → one decisive Refuge/Reposition resolution.
2. Positive GIANTS native reacquisition → recovery obligation settled; traffic responsibility remains.
3. Leader/follower boundary interaction → retained v4.7.53 gentle derived-speed Regulation.
4. Native continuation reveals a later pure established head-on.
5. Decision revises the same unresolved Commitment to REPOSITION.
6. The revision creates a fresh Native Continuation Restoration obligation and reacquires Yield actuation authority.
7. The existing Durable Separation obligation is retained, not duplicated.
8. The P22 TS015 refuge harness resolves the second head-on.
9. Stop analysis after successful second passage; subsequent diagonal cross-field behaviour is explicitly outside this prototype.

## Duplicate-dispatch boundary

The old Encounter-lifetime `HEAD_ON_REQUIREMENT_ALREADY_DISPATCHED` consumption rule is removed. Duplicate actuation is instead bounded by current execution state:

- active refuge/Reposition run → do not dispatch another;
- refuge handoff not yet positively reacquired by GIANTS → do not dispatch another;
- positive native reacquisition observed and only the long diagnostic monitor remains → that diagnostic monitor may be superseded **only after the current Operational Picture independently supports a newly established head-on resolution** (D-0128 refinement).

Native reacquisition is mechanical handoff evidence, not traffic-strategy authority. This remains a bounded test-bridge rule, not production Safe Release authority.
