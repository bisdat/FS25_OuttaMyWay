## Question

Can the active replacement-core integration exercise the Traffic Policeman capabilities on **either** of two active GIANTS AI field workers while preserving Job Episode ownership and, for spatial Reposition, positively demonstrate that a wide foldable assembly becomes compact enough to matter spatially?

The capability groups are:

1. bounded GIANTS-native Regulation apply/release;
2. same-Job Hold/release at an operator-selected stable state; and
3. participant-complete **forward spatial Reposition**: Hold → compact/configure → one bounded forward Manoeuvre Leg → compact Hold at target → restoration → same-Job GIANTS handback.

Reverse Reposition remains architecturally valid but is deliberately `UNRESOLVED` in this prototype.

## Architectural boundary

Prototype 22 does **not** implement Traffic Policeman activation, `PROGRESS`/`YIELD` role assignment, Productive Continuation Preference, preference-band selection/exhaustion, Candidate selection, a live Commitment, refuge selection, target-clearance authority or Safe Release policy.

`OuttaMyWay.CONTROL_AUTHORITY_ENABLED` remains `false`. P22 is an explicit manual diagnostic actuator and cannot arm from Situation Assessment or Decision.

## P22-C — Participant-complete forward spatial Reposition

### Fixture

Use Condor and Patriot in roomy, obviously clear space. The operator owns fixture clearance; P22 still makes no production target-clearance claim.

The selected worker must begin fully deployed and stable, with current represented plan-view span available from the passive Physical Assembly representation.

### Action

Example:

```text
otmP22 reposition Condor 8 5 5
```

### Revised sequence

```text
HOLD to translational settlement
→ disable work / raise where the tested assembly supports it
→ request compact/fold
→ positively observe actual fold motion
→ begin one bounded forward Manoeuvre Leg while folding continues
→ reach target and remain on the same Hold
→ complete full compact configuration
→ positively observe represented plan-view span reduction
→ P22-C spatial PASS / UNRESOLVED
→ manual release
→ restore original deployed/lowered/work configuration while Held
→ release Hold
→ observe same-Job GIANTS continuation
```

### Folding while moving

v4.7.36 deliberately **does not require full folding before movement**. Condor/Patriot folding takes roughly 15 seconds in the observed fixture; that time is potentially valuable Action Space. The probe therefore begins the Manoeuvre Leg once actual fold motion is observed and lets folding continue during movement.

This overlap is capability validation, not production clearance policy. A `foldAnimTime` value is diagnostic configuration-motion evidence only. It does **not** establish spatial clearance.

### Spatial PASS

P22-C spatial PASS requires both:

1. full compact/fold configuration is observed at the target; and
2. the current represented plan-view hull has a positively smaller rotation-invariant maximum span than the deployed starting footprint by the probe's diagnostic noise margin.

The span comparison is positive evidence only. It does not create negative-clearance authority or Coverage Closure. If Physical Representation cannot positively demonstrate the footprint reduction, P22-C is `UNRESOLVED` even if folding is visually apparent and the target actuator worked.

The diagnostic span-reduction margin and time bounds are prototype literals only and carry no Decision-policy authority.

### Participant-complete PASS

Full P22-C PASS requires the complete sequence for **both Condor and Patriot**. One participant's success cannot justify fixed Yield authority for that participant.

## Restoration

`otmP22 release` after a P22-C result does not immediately hand the worker back to GIANTS. P22 first unfolds/restores its owned work/lowered configuration mutations while the same Hold remains active. Only after the original deployed configuration is observed does P22 release the Hold and monitor independent same-Job continuation.

`cancel` removes movement authority, retains Hold and, if P22 owns configuration mutations, restores them while the worker remains stopped.

## Reverse boundary

Negative `forwardM` remains refused and logs `REVERSE_REPOSITION_UNRESOLVED`. Reverse remains architecturally available; only OuttaMyWay-directed reverse actuation remains unvalidated.
