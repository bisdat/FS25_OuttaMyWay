# Current replacement-core implementation risks

> **Currency:** v4.6.78 Replacement-Core Architecture Candidate

## v4.6.72–v4.6.77 branch is failed evidence

The temporary branch culminated in an illegal Commitment completion with `safeRelease=false` and renewed authority against unresolved responsibility. It is not an implementation baseline. See `EXPERIMENTAL_LINEAGE_V4.6.72-V4.6.77.md` and `50_Research/ARCHITECTURE_COMPLIANCE_AUDIT_V4.6.77.md`.

## Architecture Kernel and replay harness are absent

The next implementation blocker is not another scenario rule. The deterministic records, enforcing Commitment state machine, complete Candidate Action Space, mandatory verdicts and replay conformance suite do not yet exist.

## Replacement core is not implemented

The normative lifecycle, Obligation Set, Governing Basis, terminal settlement and Effective Actuation Composition exist only in documentation.

The active runtime remains v4.6.56. No runtime evidence should be interpreted as validation of the replacement core until implementation explicitly conforms to ADR-0019.

## Passive contract implementation is absent

No runtime structure yet provides a shared:

- Commitment identity;
- Governing Basis;
- lifecycle state;
- Obligation Set;
- terminal disposition;
- authority-composition trace.

This is the first implementation gap to address after Canonicalisation.

## Effective Actuation Composition is not enforced

Current runtime mechanisms do not universally validate proposed Control against:

- existing commands;
- capability reservations;
- residual predecessor effects;
- concurrent actions on relevant assemblies;
- complete Future-Space composition.

The never-hold-all invariant is accepted architecture but not a substitute for general composition validation.

## Representation Fitness remains incomplete

Exact or sufficiently conservative physical representation is not available for every assembly, configuration or movement sweep.

Known gaps include:

- complete collision-shape coverage;
- configuration-transition sweep;
- steering/articulation sweep;
- action-specific coverage closure;
- field containment for the complete assembly;
- candidate path occupancy.

No Silent Under-Approximation remains mandatory.

## Native Continuation Speed Estimate remains unresolved

Cruise-control maximum is not expected native continuation speed.

Implementation must discover a bounded estimate from recent unmodified GIANTS operating behaviour, phase and manoeuvre state. This is required for some counterfactual release conclusions but does not alter the replacement lifecycle.

## Reverse Actuation Discovery is deferred

Reverse is architecturally available but has not been established as a generic safe capability across supported assemblies.

No implementation may assume universal reverse authority.

## Numerical thresholds remain empirical

The architecture does not fix:

- prediction horizon;
- clearance margin;
- evidence timeout;
- settlement duration;
- motion speed;
- orientation tolerance;
- candidate scoring weight.

Each value must protect a named architectural property and remain subject to runtime validation.

## Candidate generation remains incomplete

The complete supportable Candidate Action Space is a normative requirement. Exact geometric algorithms for refuge, displacement, safe waiting and other candidates remain implementation work.

Preference-band exhaustion must not be treated as complete candidate exhaustion.

## Player communication remains undesigned

The player is not an internal Obligation owner. The architecture permits continued observation and coordination after player takeover, but any HUD/audio communication for unresolved responsibility remains a later UX design subject.

Communication must preserve the no-fuss experience and must not rely on red/green colour distinction.

## Runtime scope overlay remains absent

The reviewed semantic catalogue and Scope Overlay remain knowledge. Runtime Control Eligibility, Operation Participation, Assembly Relevance and Obstacle Relevance are not yet implemented as one general service.

## Route substitution remains out of scope

No general route planner or route-substitution capability is authorised. A future implementation must not solve lifecycle or obligation problems by silently taking ownership of GIANTS routes.

## RRS authority transformation remains human-governed

RRS Candidate Production is implemented. Accepted Candidate to canonical Authority Transformation remains owner-governed and is not automated.

## Publication readiness

`modDesc.xml` returns to a stable project description in v4.6.78, resolving the previously recorded Mod Description Drift.

Public release readiness still requires:

- implementation maturity;
- runtime validation;
- removal or isolation of development-only diagnostics;
- localisation review;
- performance validation;
- ModHub and licensing review.
