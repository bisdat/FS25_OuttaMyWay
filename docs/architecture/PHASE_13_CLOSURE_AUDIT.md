## Candidate construction and planning

Current Candidate responsibilities are now bounded to feasible option construction, planning and support provenance.

### CandidateAction boundary

`CandidateAction` explicitly rejects downstream authority fields including:

- `selected` / `selectedCandidateId`;
- `admissible` / `viable`;
- `commitmentAction`;
- `controlRequest`; and
- `constraintEvidence`.

This prevents Candidate data from carrying canonical Constraint, Decision, Commitment-operation or Control authority.

### CandidateSpace boundary

`CandidateSpace` may consume historical/transitional Candidate-support `constraintEvidence` packets because useful planning evidence still exists in mature support modules. It removes PASS/FAIL/UNRESOLVED and applicability before constructing canonical `CandidateAction`, retaining only non-authoritative evidence/reason/provenance as `candidatePlanningEvidence`.

Therefore historical fixture/support vocabulary no longer creates a second Constraint verdict path.

### Prospective Decision Portfolio

Fresh independently supportable purposes are enumerated through `ProspectiveDecisionPortfolioSupport` when no incumbent lifecycle context already narrows the support scope.

The accepted `.20` correction preserves two Reality-driven discoveries:

- **Support Projection != New Operational Picture**;
- **Support Scope != Evidence Deletion**.

Candidate Support Projections nominate one prospective governing relationship while retaining the complete parent evidence universe. All groups bind same-picture evidence directly to one Candidate-support-enriched Decision picture. No projection publishes an intermediate Operational Picture.

Candidate support therefore enumerates supportable fresh groups without deciding which fresh purpose should govern.

### Passage planning

`LocalPassagePlanner.planConflict()` owns arrangement planning inside one Established Opposed Corridor Conflict. It does not select among independently supported conflicts for the Portfolio path.

The earlier discovery remains explicit:

> **Passage Planning != Passage Conflict Selection**

Per-conflict arrangement search is Candidate planning. Nearest-supported-conflict choice is Decision policy.

### Legitimate Candidate narrowing

- incumbent lifecycle gating when an existing responsibility/obligation already owns the current lifecycle;
- same-relationship Passage before D-0146 Action-Space Regulation, because Action-Space is a fallback expression for that same governing spatial incompatibility;
- fail-closed same-class ambiguity where no accepted comparator exists.

**Verdict: distinct responsibility — retain.**

> **Commitment Operation != Responsibility Transition**
