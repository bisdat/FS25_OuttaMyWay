## Accepted Scope Overlay architecture

Read `SCOPE_OVERLAY_ARCHITECTURE.md` before selecting fixtures or designing implementation.

```text
Reviewed Semantic Catalogue
    -> Scope Overlay
        -> Control Eligibility Profile
        -> Operation Participation
        -> Assembly Relevance
        -> Obstacle Relevance
            -> targeted test and Structural Challenge selection
                -> later implementation and validation
```

The four dimensions are independent contextual claims, not four columns that can be inferred mechanically from semantic category.

### Capability and control

The capability baseline is the unmodified Giants base game. Assess the Giants AI job configuration as a whole. Job Admission and engine start are not proof of Job Configuration Viability; evidence must reach the Capability Confirmation Point where Giants controls the required working behaviour.

Control Eligibility Profile belongs in Scope Overlay for support and test selection. Runtime Control Admissibility is downstream and contextual. Known ineligibility becomes a Control Exclusion Constraint while the Entity remains represented: Observe Broadly, Control Narrowly.

### Testing

Control ineligibility does not imply test ineligibility. Select both Positive Test Candidates and a limited number of Bounded Negative Test Candidates. Negative tests should prove persistent representation, correct control exclusion, independent obstacle assessment, downstream refusal and appropriate player communication. Test admission never expands support status.

### Runtime relationships

Operation Participation is a temporal functional relationship. Presence and Operational Influence do not establish participation; obstacle influence remains independent.

A Behavioural Assembly contains the connected members whose combined state determines relevant behaviour and space. Membership, relevance and control are separate. Under the base-game baseline, implement detachment is player-mediated and triggers assembly reassessment.

Obstacle Relevance is contextual and assessed against another Entity or Operation demand. It can arise from current occupancy, Future Space or configuration transition. An Entity is not permanently an obstacle type.

### Persistent obstruction

A successful immediate diversion is Local Resolution, not necessarily Operational Resolution. Repeated return to occupied required work may establish a Persistent Spatial Constraint, Denied Work Space, Recurring Commitment Loop and Completion Blocker. When the physical change is outside OuttaMyWay's authority, the Decision Engine may need player escalation rather than indefinite repetition.
